# lncrna_rra_day14_cellline_loco leaderboard

Live page: **https://jeonglab-bcm.github.io/lncFit/lncrna_rra_day14_cellline_loco.html**
(submitter, model, description, and a per-cell-line breakdown per entry). Also
available as [`LEADERBOARD.md`](LEADERBOARD.md) for viewing directly on GitHub. Both
are auto-generated by CI -- don't edit either by hand.

## What this challenge tests

The sibling challenge, [`lncrna_rra_day14`](../../lncrna_rra_day14/leaderboard/), holds
out chromosome 1 -- it asks "does this generalize to an lncRNA the model never saw?"
This one holds out an entire **cell line** instead: for each of HAP1, HEK293FT, K562,
MDA-MB-231, and THP1 in turn, a model trained on the other 4 cell lines' rows predicts
that one. Every record ends up predicted by a model that never trained on a single row
of its own cell line. It asks a different, harder question: does this generalize to a
cell line it's never seen at all, not just a gene it's never seen?

## How to submit

1. Generate leave-one-cell-line-out predictions with `scripts/run_cellline_loco.py`
   (see `configs/cellline_loco/xgboost_kmer.yaml` for an example config) against
   `data/processed/lncrna_rra_day14.jsonl.gz` -- the **full** day14 dataset (not the
   chr1 train/test split used by the other challenge). Any model/features
   combination `lncfit.classifiers`/`lncfit.features` supports is fair game, as long
   as each cell line's predictions genuinely come from a fold that excluded it during
   training (CI can verify your `predictions.csv` covers the dataset correctly; it
   cannot verify you didn't train on a held-out cell line by mistake -- describe your
   methodology in `submission.yaml` so reviewers can check it).
2. Create a branch named `submission/<your-name-or-team>-<short-slug>` (must start
   with `submission/` -- CI only runs for those).
3. Add a new directory:
   `results/lncrna_rra_day14_cellline_loco/leaderboard/submissions/<your-name-or-team>-<short-slug>/`
   containing:
   - `predictions.csv` -- copy directly from your run's output directory
     (`results/lncrna_rra_day14_cellline_loco/runs/run_.../predictions.csv`). Needs
     `target`, `cell_line`, `y_pred_proba` for all 27,480 rows of the full dataset.
   - `submission.yaml`:
     ```yaml
     submitter: your-github-handle
     model: one-line description, e.g. "xgboost + kmer k=5"
     description: >
       how you built the 5 folds (e.g. "scripts/run_cellline_loco.py, unmodified") --
       this is the part CI can't verify, so be explicit.
     ```
     `submitter` must be an actual GitHub username (letters/digits/single-hyphens,
     no spaces) -- CI rejects anything else. It's linked to `github.com/<submitter>`
     on the leaderboard, so use your own handle (or an org/team handle), not a
     free-text display name.
   - `config.yaml` (optional but encouraged) -- copy from your run's output directory.
4. Open a PR. CI independently recomputes AUROC/AUPRC from your `predictions.csv`
   against the real labels in `data/processed/lncrna_rra_day14.jsonl.gz`, fails the
   check if the submission is malformed or doesn't cover the dataset exactly, and on
   success commits the updated `LEADERBOARD.md` back onto your PR branch.
