# lncrna_rra_day14_thp1_holdout leaderboard

Live page: **https://jeonglab-bcm.github.io/lncFit/lncrna_rra_day14_thp1_holdout.html**
Also [`LEADERBOARD.md`](LEADERBOARD.md) for viewing on GitHub. Both are
auto-generated by CI -- don't edit either by hand.

## The protocol

Train on HAP1, K562 and MDA-MB-231; predict THP1.

**This is an honour-system board, not a blind benchmark.** `label` is computed
from the *published* supplementary tables of the source screen paper
(`data/raw/mmc3.xlsx`, sheets S2F-S2J) by the rule
`rra_pvalue < 0.05 and fold_change < 0`. Anyone can therefore derive THP1's
answers from public data, and no repo-side measure changes that -- an earlier
attempt to ship the labels encrypted was abandoned as security theatre once it
was clear the same labels sit in the published supplement, in this repo's own
`data/processed/` files, and in ~38 historical `predictions.csv` files with
`y_true` columns.

What the repo *does* do is make the honest path the easy one: `data/holdout_thp1/`
provides a training file with THP1 removed and a THP1 features file with `label`
blanked to `-1`, so following the instructions never puts the answers in front of
you. Please don't go looking. A genuinely blind evaluation would need ground truth
that isn't in the paper -- an unpublished cell line, timepoint, or replicate.

HEK293FT is excluded from the challenge entirely: it isn't a real cancer cell line
(never in CCLE/DepMap) and has no Celligner coordinates.

The question is whether a model generalizes to a cell line it has never seen a
single row of -- harder than generalizing to an unseen lncRNA, and the reason
scores here sit well below what a within-cell-line split would give.

## How to submit

1. Train on `data/holdout_thp1/train_thp1_holdout.jsonl.gz` (16,488 rows across the
   3 public cell lines, labels included) and predict every row of
   `data/holdout_thp1/holdout_thp1_features.jsonl.gz` (5,496 THP1 rows).

   Any model is fair game. `scripts/run_pipeline.py` is the supported path --
   point `data.train` at the training file and `data.test` at the features file.
   Sequence features come from `data/processed/body_sequences_transcript.json`
   (k-mer) or a precomputed embedding `.npz` (see [`configs/README.md`](../../../configs/README.md)).

2. Create a branch named `submission/<your-github-handle>-<short-slug>`. The
   `submission/` prefix is required -- CI only runs for those. Open the PR **from
   a branch on this repository, not a fork**: fork PRs can't get the write access
   needed to push the regenerated board.

3. Add `results/lncrna_rra_day14_thp1_holdout/leaderboard/submissions/<your-github-handle>-<short-slug>/`
   containing:
   - `predictions.csv` -- needs `target`, `cell_line`, `y_pred_proba` for all
     5,496 THP1 rows. An extra `y_true` column is ignored; scoring never trusts it.
   - `submission.yaml`:
     ```yaml
     submitter: your-github-handle
     model: one-line description, e.g. "xgboost + DNABERT-2 + distance-to-gene"
     description: >
       what you did -- especially anything CI cannot verify, like how you built
       features or whether you used the training file unmodified.
     ```
     `submitter` must be a real GitHub username (letters/digits/single-hyphens, no
     spaces); CI rejects anything else and links it on the board.
   - `config.yaml` (optional but encouraged) -- the exact config you ran.

4. Open the PR. CI recomputes AUROC/AUPRC from your `predictions.csv` against the
   real labels, fails the check if the submission is malformed or doesn't cover
   the 5,496 rows exactly, and on success commits the updated `LEADERBOARD.md` and
   live page onto your PR branch.

## How to read the scores

THP1 has **202 positives**, so a single-run AUPRC carries a 95% bootstrap
confidence interval roughly ±0.02 wide. **Treat gaps smaller than that as noise.**

On the older chromosome-held-out split, cross-validation ranking and test AUPRC
came out perfectly *anti*-correlated (Spearman -1.0) across an SVM `C` sweep --
configs scoring higher on test were the ones CV liked least, because with ~100
positives a couple of genes landing differently moves the metric more than a real
modelling improvement does. See the "AUPRC does not respond to model selection"
section of [`configs/README.md`](../../../configs/README.md). Don't tune against
the leaderboard; select with CV on the training cell lines, or with multi-seed
means.

## Regenerating the split

```bash
python scripts/split_holdout_cellline.py --holdout THP1 --out data/holdout_thp1
```

The script also writes `holdout_thp1_labels.jsonl.gz`; it is deliberately **not**
committed, since scoring reads THP1's rows from
`data/processed/lncrna_rra_day14.jsonl.gz` instead. It exists for the case where a
future challenge holds out genuinely unpublished data and the labels really do
need to live somewhere private.
