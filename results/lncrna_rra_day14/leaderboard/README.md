# lncrna_rra_day14 leaderboard

Live page: **https://jeonglab-bcm.github.io/lncFit/lncrna_rra_day14.html** (submitter,
model, description, and a per-cell-line breakdown per entry). Also available as
[`LEADERBOARD.md`](LEADERBOARD.md) for viewing directly on GitHub. Both are
auto-generated by CI -- don't edit either by hand, they get overwritten on the next
valid submission.

## How to submit

1. Train a model with `scripts/run_pipeline.py` (see [`configs/README.md`](../../../configs/README.md))
   against `data/processed/train_lncrna_day14_chrom1.jsonl.gz`, evaluated on
   `data/processed/test_lncrna_day14_chrom1.jsonl.gz`. Any model/features/tuning/CV
   combination the pipeline supports is fair game.
2. Create a branch named `submission/<your-name-or-team>-<short-slug>` (the branch
   name **must** start with `submission/` -- CI only runs for those).
3. Add a new directory:
   `results/lncrna_rra_day14/leaderboard/submissions/<your-name-or-team>-<short-slug>/`
   containing:
   - `predictions.csv` -- copy this directly from your pipeline run's output
     directory (`results/lncrna_rra_day14/pipeline_runs/run_.../predictions.csv`).
     Needs the `target`, `cell_line`, `y_pred_proba` columns for every row in the
     held-out test set -- nothing more is required (an extra `y_true` column, if
     present, is ignored; scoring never trusts it).
   - `submission.yaml`:
     ```yaml
     submitter: your-github-handle
     model: one-line description, e.g. "xgboost + kmer k=5 + Celligner UMAP"
     description: optional longer note -- what you tried, what changed, etc.
     ```
     `submitter` must be an actual GitHub username (letters/digits/single-hyphens,
     no spaces) -- CI rejects anything else. It's linked to `github.com/<submitter>`
     on the leaderboard, so use your own handle (or an org/team handle), not a
     free-text display name.
   - `config.yaml` (optional but encouraged) -- the exact pipeline config you ran,
     for reproducibility. Just copy it from your run's output directory too.
4. Open a PR. CI will:
   - independently recompute AUROC/AUPRC from your `predictions.csv` against the
     real held-out labels (it never trusts a submitted `metrics.csv` or `y_true`),
   - fail the check if your submission is missing a required file, has the wrong
     columns, or doesn't cover the test set exactly (missing/extra/duplicate rows),
   - if valid, commit the updated `LEADERBOARD.md` back onto your PR branch.
5. Once CI is green, get it reviewed and merged like any other PR.

## Why predictions.csv, not a training script

Submitting predictions rather than code keeps scoring simple and uniform regardless
of how you produced them -- you can use `scripts/run_pipeline.py`, an older script,
or something entirely custom, as long as the output has the three required columns
for every held-out row.
